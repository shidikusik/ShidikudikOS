# Оборудование: что работает и что нет

ShidikusikOS собирается на ядре Debian и включает все свободно
распространяемые прошивки, поэтому большинство железа работает «из
коробки». Ниже — что именно входит в образ и что делать, если
конкретное устройство молчит.

## Что входит в образ

| Категория | Пакеты |
|---|---|
| Прошивки | `firmware-linux`, `firmware-misc-nonfree`, `firmware-iwlwifi` (Intel), `firmware-realtek`, `firmware-atheros`, `firmware-brcm80211` (Broadcom), `firmware-sof-signed` (звук Intel) |
| Микрокод | `intel-microcode`, `amd64-microcode` |
| Wi-Fi | NetworkManager + `wpasupplicant`; управление — шторка (Win+N) или Shidik-Control |
| Bluetooth | `bluez`, `bluez-tools`, `rfkill`; переключатель в шторке, сопряжение — в Shidik-Control |
| Видео | Mesa (Intel, AMD, Nouveau, virtio-gpu). NVIDIA — проприетарный драйвер ставится вручную, см. ниже |
| Звук | PipeWire + WirePlumber |
| Печать | CUPS + Avahi (сетевые принтеры) |
| Носители | NTFS, exFAT, Btrfs, ext4, автомонтирование через udisks2 |

## MediaTek MT7902 — честно о проблеме

**Wi-Fi и Bluetooth на MT7902 не заработают ни в ShidikusikOS, ни в
любом другом дистрибутиве Linux.** Это не наша недоработка и не вопрос
установки пакета: **драйвера этого чипа в ядре Linux не существует**.

- MediaTek выпустила драйверы для MT7921/MT7922/MT7925 — они в ядре
  есть и работают. Для **MT7902** производитель не выпустил ни драйвера
  в ядро, ни исходников.
- В сети встречаются «сборки под MT7902» — это неработающие форки
  драйвера mt7921 или обёртки над Windows-драйвером. Ни один из них не
  собирается с современным ядром и не даёт стабильной работы.
- Прошивка из `linux-firmware` для MT7902 присутствует, но без драйвера
  она бесполезна: некому её загружать.

**Что реально можно сделать:**

1. **USB Wi-Fi адаптер** — самый простой путь. Работают «из коробки»
   любые на чипах Realtek RTL8811/8812/8821, Ralink RT5370, Intel AX200
   (M.2), MediaTek MT7921AU. Стоят недорого, втыкается в USB.
2. **Заменить модуль M.2** — если в ноутбуке слот M.2 2230 Key A/E,
   карта Intel AX200/AX210 встаёт на место MT7902 и работает идеально
   (прошивка `firmware-iwlwifi` уже в образе). Это лучшее решение для
   постоянного использования.
3. **USB-Bluetooth донгл** — на чипе CSR8510 или Realtek RTL8761,
   работают сразу.
4. **Проводной Ethernet** — если нужен только интернет.

Проверить, какой именно чип стоит:

```sh
lspci -nn | grep -i net      # PCI/M.2 адаптеры
lsusb | grep -i -E 'wire|blue'
```

Если в выводе `14c3:7902` — это тот самый MT7902.

## USB-модемы и мобильный интернет

Работает без единой настройки:

| Способ | Как подключить |
|---|---|
| **Android как USB-модем** | воткнуть кабель → на телефоне включить «USB-модем» → соединение появится само как проводное |
| **Свисток HiLink** (Huawei E3372h, многие МТС/Мегафон/Билайн) | воткнуть — он притворяется сетевой картой, настройки не нужны |
| **iPhone как USB-модем** | воткнуть, на телефоне «Доверять этому компьютеру» (работает через `usbmuxd`) |
| **Классический LTE-свисток** в режиме модема | Настройки → Сеть → «Мобильный интернет» → «Найти модемы» → «Подключить…» и указать APN |

Под капотом: `usb-modeswitch` выводит свисток из режима «виртуального
CD-привода», `ModemManager` поднимает модем, NetworkManager создаёт
соединение. Всё это включено в образе.

APN основных операторов уже подсказаны в диалоге подключения. Если
оператора нет в списке — APN написан в договоре или на сайте оператора.

Проверить, видит ли система модем:

```sh
mmcli -L            # список модемов
nmcli device        # все сетевые устройства
lsusb               # что вообще подключено по USB
```

Если свисток определяется как `usb-storage` и не переключается —
попробуйте `sudo usb_modeswitch -v <vid> -p <pid> -J`, где vid/pid видны
в `lsusb`.

## NVIDIA

Открытый `nouveau` работает для рабочего стола, но без нормального 3D.
Проприетарный драйвер ставится штатно:

```sh
sudo apt install nvidia-driver firmware-misc-nonfree
```

После установки Wayland-сессия требует `nvidia-drm.modeset=1` в
параметрах ядра (`/etc/default/grub`, затем `sudo update-grub`).

## Если устройство не определилось

```sh
# что за железо
lspci -nnk | less
lsusb

# что говорит ядро при загрузке
sudo dmesg | grep -i -E 'firmware|failed|error' | less
```

Обычно в `dmesg` прямо написано, какого файла прошивки не хватает —
дальше `sudo apt search` по его имени. Если пакет нашёлся, он ставится
через Shidik-Store или `sudo apt install`.
